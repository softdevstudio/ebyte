# EByte schema library

Ready-made schemas for real formats, each tested against the real sample file in `samples/`: the test decodes the sample and encodes it back to identical bytes on every CI run.

| Schema | Describes | Sample | Limits in schema version 1 |
|---|---|---|---|
| `pcm-wav.schema.json` | Plain PCM WAV with the 44-byte header: RIFF, fmt and data chunks in that order | `tone.wav`, 0.1 s of a 440 Hz tone, made with Python's `wave` | No extra chunks such as `LIST`; `riff_size` and `data_size` are derived (EByte 0.3.0); `byte_rate` and `block_align` are edited by hand |
| `bmp-24bit.schema.json` | Uncompressed 24-bit BMP with the 40-byte info header, rows bottom-up or top-down | `stripes.bmp`, 5 x 3 pixels, made with Pillow | Pixel data must start at offset 54; `file_size` and `image_size` are derived (EByte 0.3.0); width and height must match the pixel data, edited by hand |
| `riff-wave.schema.json` | Any RIFF WAVE file as a list of chunks (`fmt `, `data`, `LIST` and others in any order), each with its id, size and raw body; needs EByte 0.2.0 | `tagged.wav`, the same tone plus a `LIST`/`INFO` chunk with a title and software name | Chunks with an odd size, whose pad byte isn't counted in the size, aren't supported; chunk bodies are raw hex; `riff_size` and each chunk size are derived (EByte 0.3.0) |
| `zip.schema.json` | A ZIP archive with any number of entries: local headers and data, central directory, end record; needs EByte 0.2.0 | `three.zip`, three files (two stored, one deflated) and an archive comment, made with Python's `zipfile` | No data descriptors (flag bit 3), ZIP64, split archives or bytes between entries; CRC-32 isn't checked, because for compressed entries it covers the uncompressed data; name, extra, comment and data lengths, the entry counts and the directory size and offset are derived (EByte 0.3.0); the central directory's copy of each size and each entry's local header offset are edited by hand |
| `png.schema.json` | Any PNG as its signature and a list of chunks (`IHDR`, `tEXt`, `IDAT`, `IEND` and others), each with its type and raw data; needs EByte 0.4.0 | `stripes.png`, 4 x 3 pixels with a text comment and a DPI chunk, made with Pillow | Every chunk length and CRC-32 is derived; image data stays zlib-compressed hex, so pixels can't be edited directly |
| `pcap.schema.json` | A classic libpcap capture (little-endian, microsecond timestamps) as its global header and a list of packet records, each with timestamps, lengths and the raw frame; needs EByte 0.3.0 | `sensor.pcap`, three UDP status packets from a sensor, built with Python and read back with dpkt | Big-endian and nanosecond captures and pcapng aren't covered; `incl_len` is derived, `orig_len` is kept as stored; frames are raw hex |
| `wav-float32.schema.json` | A 32-bit float WAV (format 3) with fmt and data chunks, every sample as an f32 value; needs EByte 0.6.0 | `tone-float.wav`, 400 samples of a 440 Hz tone at amplitude 0.5, built with Python's struct | No extra chunks and no fact chunk; `riff_size` and `data_size` are derived; `byte_rate` and `block_align` are edited by hand |
| `bmp-8bit.schema.json` | An uncompressed 8-bit paletted BMP; the palette runs from the end of the 40-byte info header up to `pixel_offset`; needs EByte 0.6.0 | `palette.bmp`, 6 x 2 pixels in four colours, saved by Pillow | `pixel_offset` and `colors_used` are edited by hand when the palette size changes; `file_size` and `image_size` are derived |
| `zip-one-stored-file.schema.json` | A ZIP holding exactly one stored (uncompressed) file: local header, data, central directory, end record | `one.zip`, `hello.txt` made with Python's `zipfile` | One entry only; every length, size, offset and both CRC-32 copies are derived (EByte 0.4.0), so editing the file's text needs nothing else |

```sh
ebyte inspect --schema schemas/pcm-wav.schema.json --input recording.wav --format text
```

Derived values are checked on decode, so a file with a stale size, offset or checksum fails at that field; to read such a file anyway, delete that field's `derive` and the value becomes an ordinary editable integer. The case studies on [ebyte.org](https://ebyte.org/) walk through each schema on its sample. New schemas need a sample and an entry in `schema_library_test.go`.
