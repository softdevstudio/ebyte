# EByte releases

EByte v0.1.0 is the first implemented release under Apache License 2.0. Public release titles use EByte vX.Y.Z and archives have no version in their filenames. Linux amd64/arm64 and macOS amd64/arm64 use tar.gz; Windows amd64 uses zip. Each archive contains the CLI, manual, license/notice files, examples, release.json and GO-NOTICES from the exact building toolchain. No external Go modules are linked.

Release waits for successful Linux/macOS CI on the same current main-push SHA. Independent review is a session gate recorded in CLAUDE.md. Separate packaging jobs test the library and native CLI on Linux, macOS and Windows. Native binaries are checked again after extraction; the other architectures are explicitly cross-built and unexecuted. release.json and RELEASE-MANIFEST.json record actual host verification rather than implying every archive ran natively. A clean checkout and embedded Go VCS revision bind binaries to the tested source. Build candidates using --local are forbidden in Actions and rejected by the publication validator.

The final gate validates all five archives, project licenses, exact-toolchain notice hashes and embedded build information. SHA256SUMS covers the five archives and RELEASE-MANIFEST.json; it excludes itself. Uploads go to a draft first, and successful uploads are verified by server digest or an authenticated download before publication. A failed draft is deleted, along with an owned matching tag if created. A failure after publication is reported for investigation and never silently deletes the published release. A cleanup failure records the remaining release/tag identifiers. No version bump is used merely to retry a gate before publication.

After publication, automation downloads every asset at the explicit tag and latest, compares hashes, checks the exact tag/source/name and executes a downloaded native CLI through schema validation, round trip, inspect, failure, limit and file-output behavior. Public verification is saved in one test/results/ebyte-{version}-release folder; latest/ remains the ordinary recorder output. Those checks do not constitute a signature or a general supply-chain guarantee.

Windows supports file input and stdin/stdout but --output FILE publication deliberately fails closed. Linux/macOS file publication requires same-directory hard links and a trusted parent directory. Native smoke explicitly checks that distinction. There is no power-loss directory durability promise, no automatic format discovery and no structural diff or graphical editor in v1. Context checks cannot interrupt arbitrary blocked library I/O; full-pipeline allocation evidence is not a peak-memory or throughput guarantee.
