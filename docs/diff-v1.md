# Structural diff

Since EByte 0.5.0, Plan.Diff(ctx, before, after io.Reader) returns (*DiffResult, error) and the CLI command diff compares two binary inputs through one schema. Both inputs are decoded completely with the same plan and limits, each under its own budgets, before anything is compared. If either decode fails, Diff returns a *DiffError whose Input is "before" or "after" and whose Diagnostic is that decode's diagnostic; nothing is compared and no partial result is returned. Before is decoded first, so when both are invalid only before's failure is reported.

A diff result has exactly diff_version (integer 1), schema_sha256, state ("same" or "different"), size_before and size_after (input byte counts) and changes (array). state is "same" exactly when changes is empty. Because unchanged decode/encode is lossless, two accepted inputs have no changes if and only if their bytes are identical.

Comparison walks the schema in field order, the same preorder as a trace, and compares what each input decoded: integers by their decimal value, bytes and strings by their raw bytes. Derived integers (counts, sizes, offsets, checksums) are compared too, from their stored values, and marked derived, so a single edit can appear with the sizes and checksums that follow from it. Fields that are equal produce nothing, even when they moved to another offset. Arrays and repeats are matched by position: element i of before is compared with element i of after, and elements past the shorter list are added or removed. Inserting an element in the middle of a list therefore reports every later element as changed; there is no reordering or alignment by content in this version.

Each change has exactly path (RFC 6901 pointer, as in traces), kind (the field's trace kind: struct, array, repeat, bytes, string or an integer type), change ("changed", "added" or "removed"), derived (boolean), before and after, plus first_difference only where stated. before and after are spans {offset, length} from that input's trace, with value (decimal string) only for integers; a span is null on the side where the field is absent.

- changed: the field exists in both inputs with a different value. For bytes and strings, first_difference is the zero-based byte index within the field where they first differ, or the shorter length when one is a prefix of the other; contents are never included.
- added: present only in after, for example an extra repeat element or a conditional field whose condition became true. A container is reported once at its own path, not field by field.
- removed: present only in before.

Field contents other than integers stay out of diff output, the same rule as traces and diagnostics. The number of changes is bounded by MaxTraceEntries and the CLI checks the serialized result against MaxTraceBytes; Diff applies no new limits of its own. Cancellation during comparison, and more changes than MaxTraceEntries, are reported with stage diff (codes cancelled and limit_exceeded) and no result.

The CLI form is ebyte diff --schema FILE --before FILE|- --after FILE|- [--format json|text] [--output FILE|-]. At most one of before and after may be stdin. Exit 0 means the inputs are the same and exit 5 means the comparison completed and found differences; the result is written in both cases. A decode failure writes {"diff_version":1,"input":"before"|"after","diagnostic":{...}} as one line on stderr and uses the diagnostic's usual exit code (1, 2, 3 or 4). The text format starts with a summary line, "EByte diff state=... schema_sha256=... size_before=... size_after=... changed=N added=N removed=N", followed by one line per change: the change, the quoted path, the kind, a=offset+length and b=offset+length (or a=- / b=- when absent), "value=X->Y" for integers, "first_difference=N" for bytes and strings and "derived" when it applies.
