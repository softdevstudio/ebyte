# Editable document and round trips

This is the proposed v1 document contract. No codec is implemented yet. The document is strict UTF-8 JSON with exactly document_version (integer 1), schema_sha256 (64 lowercase hex characters binding the exact validated schema file) and values (object). Duplicate/unknown members, nulls, invalid Unicode, trailing documents and unsupported values fail. The schema defines which nested value names exist; object member order is immaterial. Decimal integers inside values are always JSON strings, including 8-bit/count values, so 64-bit values never pass through floating-point JSON numbers. Decimal grammar is 0 or -?[1-9][0-9]*, checked against signedness/range; no plus, leading zeros, negative zero, whitespace, exponent or fraction.

Byte values are lowercase even-length hex strings, strings preserve exact characters, and arrays contain objects matching their field schema. All active non-derived values are required. Inactive conditional values and derived counts must be absent, not null. Unknown value fields fail. Decode omits a derived count from values but includes its actual stored value in inspection output. Adding an array element thus updates a derived count on encode without a second editable source of truth. Stored counts remain supplied values and a mismatch fails.

For every accepted binary input and unchanged emitted document under the identical schema bytes, encode must reproduce every input byte. No hidden normalization or discarded trailing data is allowed. Explicit reserved bytes, padding, NULs and fixed-width spaces survive. A changed schema identity is an error. Invalid UTF-8/ASCII files are not supported round-trip inputs for string fields; use bytes for opaque content instead. After a document edit, encoding changes the edited field and any declared derived counts and shifts later fields as necessary. It preserves other explicit values, not absolute offsets after variable-length edits.

Successful decode requires exact consumption of the described input. Probe at most one additional byte after the schema completes: report trailing_data rather than silently discarding it, or limit_exceeded if the probe exceeds the configured input budget. Do not drain an unbounded stream. Empty fields and an empty root schema are valid; an empty schema accepts only an empty binary input.

Inspect returns a separate trace, not extra trusted fields in the editable document. Trace is deterministic preorder: root path "", then fields in schema order, array container, each element object and its children. Paths are RFC 6901 JSON pointers such as /records/1/temperature. Each entry includes path, kind, offset, length and state complete or failed. Integer observations include their decimal string; raw string/byte contents are omitted by default. Conditions that are false have no trace node. Empty arrays and zero-length active fields do have zero-length entries. Parent spans include consumed child bytes; after failure mark the affected parent chain failed and preserve completed earlier nodes. No node claims bytes that were never consumed. Trace and editable documents have separate serialized-output limits.

The CLI must not publish a partial success document on stdout and then report a decode failure as if it were valid editable JSON. Failure diagnostics/partial traces use an explicitly separate error result or stderr format. Inspect may emit a well-labelled failed trace with nonzero exit. Filesystem output guarantees belong to the CLI; library io.Writer failures may leave partial output. Failed encode must never silently replace an unrelated destination.

The trace envelope always has exactly trace_version (integer 1), schema_sha256, state (complete/failed), entries (array) and diagnostic (null on success, otherwise the diagnostic in errors-v1.md). An entry always has exactly path, kind, offset, length and state, plus value only for an integer whose full representation was read. Kinds are struct, array, bytes, string or one declared integer type. A fully read integer that fails expect may have its observed decimal value; a truncated integer has no value. Byte/string/container entries never have value, including on failure. A failed trace includes one diagnostic and the affected parent chain marked failed; it is not a valid editable document and the CLI exits nonzero. If a limit prevents another entry, retain only already-budgeted entries and associate the diagnostic with the failed field path without inventing an entry or span. Valid partial observations must remain explicitly labelled failed; serialization failure itself must never emit a misleading complete result.
