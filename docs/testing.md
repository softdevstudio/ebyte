# EByte testing and resource reference

Run bash scripts/record-results.sh from the repository with the pinned Go toolchain. It replaces test/results/latest, records the source fingerprint and real checks, and saves the compiled CLI demo and isolated resource observations. CI runs the same script on native Linux and macOS. No release or performance claim follows merely from passing these checks.

## Independent expectations and adversarial tests

The original packet, wide, empty and stored fixtures specify bytes, editable values and schema identity independently of the interpreter. The packet's trace and edited output were also specified before implementation. All twelve acceptance vectors execute against the real compiler, decoder or encoder, while manual fixed-layout checks retain an independent byte/offset oracle. A matching decoder/encoder bug could otherwise pass a round-trip-only test.

Tests cover every packet truncation boundary, invalid string encodings, integer extrema and malformed representations, assertions, null/duplicate/unknown JSON, source scope and derived/stored count bindings. They check exact and one-less byte/node/entry ceilings, JSON escaping, zero-width fields, empty objects, nested failure states and huge dynamic dimensions rejected after reading only the dimension's eight bytes. Repeated derived counts test independent value-node and trace-entry accounting. Cancellation, no-progress, unexpected-EOF and malformed readers, short/failed/invalid writers, broken process pipes and blocked-stdin SIGINT/SIGTERM cancellation are exercised separately. When a failed trace can't be rendered within its ceiling, inspect must report the decode failure rather than the rendering limit.

Eight fuzz targets run for five seconds each with two workers. FuzzCompile challenges strict schema parsing; FuzzDecodePacket checks failure spans and result integrity; FuzzLoadAndEncode challenges editable JSON; FuzzLosslessPacket checks accepted packet bytes; FuzzLosslessShapes varies integer width/signedness/endian, stored/derived arrays, dynamic byte lengths, conditionals, nested arrays, fixed strings and assertions. Its integer observations are checked against encoding/binary independently of the codec. FuzzRepeat checks that inputs accepted by an end-of-input chunk schema and a tag-repeat schema re-encode to the same bytes and that no trace span passes the input. FuzzDerivedSizes builds documents with names and items of varying length, encodes them, checks every derived size, offset and count against the output with encoding/binary, and decodes the output back to the same values. FuzzCLIArguments checks option parsing without performing arbitrary filesystem operations. The shape harness bounds generated payloads to 4096 bytes, and argument fuzzing bounds strings to 8192 bytes; larger accepted cases are exercised by resource cases. Fuzzing is bounded evidence, not a proof that all possible inputs are safe.

Publication tests use per-call operations rather than global mutable hooks. Injected failures cover create, mode change, sync, close, link, cleanup before/after linking and cancellation after sync. No pre-link failure publishes a destination. A cleanup failure after linking preserves the complete new destination and reports that it and a staging file may remain. Cleanup failure before linking is also reported, rather than disappearing behind an earlier error. Existing-file/symlink/directory and concurrent-destination tests retain real filesystem checks. Parent renames stay anchored to the opened directory. Hostile mutation of entries inside that directory and power-loss directory durability remain outside the guarantee. Unsupported platforms/filesystems fail closed.

## Isolated resource cases

```sh
go build -o /tmp/ebyte-resourcecheck ./internal/resourcecheck
python3 scripts/resources.py /tmp/ebyte-resourcecheck /tmp/ebyte-resources.json
```

The internal resource runner is an evidence helper, not a product binary or a release asset. Each case runs in a fresh process with one sample. Accepted byte-field cases use sizes 0, 64 KiB, 1 MiB, 8 MiB and exactly 16 MiB with a deterministic repeating-byte payload. A 1 MiB ASCII string of NUL bytes demonstrates sixfold JSON escaping. The empty-elements case materializes 65536 empty objects from an empty binary. The node-limit case reaches the configured value-node ceiling with zero-width fields; the trace-limit case lowers trace entries to 32. The huge-field-limit case declares the maximum u64 length and must reject it after reading only its eight-byte header.

Accepted cases run decode, compact document serialization, strict document reload, encode, byte comparison and compact trace serialization. Rejection cases assert limit_exceeded, no editable result and no binary output; returned traces are checked against their independent budgets. Observations include input/output bytes and hashes, schema identity, document/trace byte sizes, trace entries, input read counts, elapsed nanoseconds, total Go allocated bytes/allocation count, heap allocation/reservation snapshots before and after, GC cycles, Go version, OS/architecture, logical CPUs, GOMAXPROCS and effective limits. Fixture/schema construction and hashes are outside the timed/allocation-delta interval; heap snapshots still include live fixtures and plans. Process startup is also excluded.

Cumulative allocated bytes include allocations later freed. HeapAlloc is a snapshot of currently allocated Go heap objects; HeapSys is memory reserved for the Go heap, not process RSS. Neither is peak resident memory, and no hard OS memory limit is imposed. GC timing and environment affect observations, so recorded time/heap/allocation totals are not pass/fail performance thresholds. Materialized documents, traces, compact JSON and prepared output buffers can require many times the input size across the pipeline. The results make those costs visible without implying streaming, constant memory or general throughput.
