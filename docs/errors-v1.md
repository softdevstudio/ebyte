# Diagnostics contract

The planned diagnostic has diagnostic_version 1, stage (schema/decode/encode/io), code, path, offset, field_start, expected and observed. Paths are JSON pointers. offset is a binary failure position when known, otherwise null; field_start is the affected field's start when known, otherwise null. Invalid schema/document JSON uses null binary locations; schema paths identify schema properties. All locations are nonnegative byte positions, not character indices.

Codes initially cover invalid_schema, invalid_document, schema_mismatch, constraint_mismatch, truncated_input, trailing_data, invalid_encoding, value_out_of_range, count_mismatch, limit_exceeded, cancelled, read_failed, write_failed and destination_exists. Error precedence follows execution order with schema validation before input reads and resource/range checks before allocation or consuming the affected field. A real reader error is read_failed, not EOF. Unexpected EOF is truncated_input. A short write with nil error is write_failed. Cancellation never becomes an apparent successful partial result.

For truncation, offset is the first unavailable byte (observed EOF position), field_start is the start of the incomplete field, expected describes its requested total length and observed describes available bytes. A root trailing byte has offset at the first extra byte and path "". Invalid string encoding points to the first invalid byte within the field. Byte literal mismatch points to its first differing byte; integer literal mismatch points to the field start. Range/count/limit failures during encode may have null locations until an output position is established. A trace's failed field length records only consumed bytes, even if constraint validation happened after reading the whole field.

expected/observed are bounded descriptions of at most 96 Unicode scalar values each, with JSON escaping on machine output. Describe lengths, ranges or condition kinds by default; do not dump source bytes, string values, filenames, schema literals or secret-bearing command arguments. No raw input preview is enabled in v1. Inspection of integer values is explicit inspect output rather than automatic error logging. An implementation must not falsely fill unknown offsets with zero. CLI exit 0 means the requested operation completed; 1 is runtime/I/O failure, 2 is usage/schema/document/representation validation failure, 3 is cancellation and 4 is a resource limit. Version/help and unavailable-command handling are the only implemented exits so far; future commands must follow this contract.
